# Итоговый проект Data Engineer

## Описание

Проект реализует обработку потока финансовых транзакций и курсов валют с последующим формированием аналитической витрины для анализа финансовой активности.

Поток данных:

`Yandex Managed Kafka -> RAW -> STG -> DDS -> CDM -> Metabase`

Оркестрация обработки `RAW -> STG -> DDS -> CDM` выполняется Apache Airflow.

## Технологии

- Python 3.12
- Yandex Managed Kafka
- ClickHouse 25.8
- Apache Airflow 2.11
- Metabase

> **Примечание:** в исходном задании в качестве хранилища указана Vertica.
> В проекте осознанно использован ClickHouse — open-source колоночная СУБД, которую легко развернуть локально в Docker. Это позволило собрать всё окружение проекта в одном `docker-compose.yml` и упростить воспроизведение и проверку проекта.

## Слои данных

### RAW

В `raw.kafka_events` записываем сообщения Kafka без изменения исходного JSON, дополнительно фиксируем topic, partition, offset

RAW loader:
- читает Kafka через SASL_SSL;
- записывает данные batch по 5000 сообщений или по таймауту 30 секунд при неполном batch;
- коммитит Kafka offset только после успешной записи batch в ClickHouse;
- перед вставкой проверяет `(topic, partition, offset)` и не записывает уже сохранённые сообщения повторно.

### STG

В STG исходные JSON-сообщения разбираются на две сущности:

- `stg.transactions`;
- `stg.currencies`.

Загрузка выполняется инкрементально по Kafka offset.

Для транзакций и курсов используются независимые checkpoints в Airflow Variables:

- `stg_transactions_last_offset`;
- `stg_currencies_last_offset`.

Размер пачки данных задаётся переменной `stg_batch_size`.

### DDS

DDS содержит подготовленные данные для аналитики:

- `dds.transactions`;
- `dds.currencies`;
- `dds.dim_currency`;
- `dds.dim_calendar`.

Перед обработкой очередного дня Airflow Sensor проверяет, что STG уже содержит данные следующих суток как для транзакций, так и для курсов. Это защищает от обработки неполного дня.

Транзакции и курсы загружаются через shadow-таблицы:

`очистка shadow partition -> загрузка -> REPLACE PARTITION`

Такой механизм позволяет безопасно повторно пересчитать отдельную дату.

При загрузке транзакций также:

- удаляются полные дубли через `DISTINCT`;
- исключаются тестовые аккаунты с отрицательными номерами.

После загрузки отдельные Airflow tasks проверяют, что за обработанную дату в DDS присутствуют транзакции и записи курсов валют.

### CDM

В CDM формируется витрина `cdm.global_metrics` с агрегацией по дате и валюте.

Поля витрины:

- `date_update` — дата расчёта;
- `currency_from` — код валюты транзакции;
- `amount_total` — общая сумма транзакций по валюте в USD;
- `cnt_transactions` — количество транзакций по валюте;
- `avg_transactions_per_account` — среднее количество транзакций на аккаунт (пользователя);
- `cnt_accounts_make_transactions` — количество уникальных аккаунтов (пользователей), совершивших транзакции в данной валюте.

CDM также загружается через shadow-таблицу:

`очистка shadow partition -> расчёт -> REPLACE PARTITION`

DAG `dds_to_cdm` ожидает успешного завершения соответствующего `stg_to_dds`.

После расчёта выполняется проверка полноты курсов: для каждой валюты с успешными транзакциями должен существовать прямой курс пересчёта в USD. При отсутствии курса DAG завершается с ошибкой.

## Данные для BI

Для Metabase используется представление `cdm.v_global_metrics`.

Оно объединяет календарь и справочник валют, поэтому каждая дата представлена для всех валют. При отсутствии транзакций значения метрик заполняются нулями.

Дашборд показывает:

- общий объём транзакций в USD;
- количество транзакций;
- среднее количество транзакций на пользователя;
- количество уникальных пользователей.

Доступны фильтры по дате и валюте.

## Запуск

CA-сертификат для подключения к Yandex Managed Kafka находится в репозитории:

`certs/YandexInternalRootCA.crt`

Для запуска проекта:

```bash
docker compose up -d --build
```

После запуска доступны:

- Airflow — `http://localhost:8080`
- Metabase — `http://localhost:3000`
- ClickHouse — `http://localhost:8123`

Airflow:

```text
login: admin
password: admin
```

Остановка проекта:

```bash
docker compose down
```

`reset_kafka_offsets.py` для полного replay данных из Kafka.

## Структура проекта

- `dags/` — DAG Apache Airflow;
- `src/py/raw_loader/` — Kafka -> RAW;
- `src/py/stg_loader/` — RAW -> STG;
- `src/py/dds_loader/` — STG -> DDS;
- `src/py/cdm_loader/` — DDS -> CDM;
- `src/sql/ddl/` — DDL объектов ClickHouse;
- `src/sql/scripts/` — SQL загрузки и проверок;
- `src/img/` — скриншот дашборда;
- `certs/` — CA-сертификат Kafka;
- `docker-compose.yml` — инфраструктура проекта.
